          MQTT Lifecycle Workbench 1.1.0 · Created by Jason Stys · github.com/JasonStys. Local
          plaintext project files; one trusted OS owner. Queues/counters are scoped to each

Using the lifecycle workbench

          

            Choose a prepared input inside this full application or edit its identities, queue
            settings and ordered event JSON. Validate/apply before replay. Previous/Next replays an
            isolated exact prefix, so stepping backward never mutates prior evidence.
          

          

            Allowed operations: connect, disconnect, crash, subscribe, unsubscribe, new-consumer,
            publish, checkpoint, restore, restart-broker, duplicate-last and inspect. Events use
            nondecreasing simulated atMs offsets; publish metrics retain their own explicit
            sourceTimestamp. An illegal transition is displayed as a rejected operation, never a
            successful result.
          

          

            Checkpoint requires an offline publisher. Restore requires an existing checkpoint and
            replaces only an offline publisher with a fresh process. TTL expiry occurs on original
            queue operations, not a timer. Counts after process replacement belong to that new
            process; inspect the restore event for expired/shrink losses.
          

          

            Load saved revision before Save. Imported input is not saved automatically. Exports use
            new files and preserve existing destinations. In a browser, input is memory-only and
            downloads are explicit. Native storage holds one current configuration and a previous
            complete revision, without production accounts.
          

          

            Bounds: 64 KiB project; 1–128 events within 24 simulated hours; 1–1000 queue capacity;
            1–16 validated metrics per publish. The original seven independent scenarios remain
            below. No real MQTT adapter is invoked.
