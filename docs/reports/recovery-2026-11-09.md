The independent fixture was handwritten, not exported and immediately reimported as the sole test.
It validates exact TTL boundaries, both receiving capacity policies, invalid ordinals/lifetimes,
identity mismatch, duplicate/future restores, invalid JSON/unknown fields/1 MiB limit, clock regression,
no partial state replacement, input/output deep copies, uint32 birth exhaustion and 260 replayed
batches across modulo-256 sequence wrap. A deliberately thrown actual broker publication preserves
the batch; `retryBuffered()` publishes it successfully once the broker accepts it. The integration
fixture checks the consumer's final value and wire metadata after reading actual saved file bytes.

No live broker, device, external credentials or operating-system setting was used or changed. No
Docker repair, deployment or host collector was run. The new Node 22/24 CI step invokes the actual
file rehearsal in addition to every original gate. Hosted matrix/CodeQL checks have not been
triggered by this agent; they are for the parent publishing review. The external MQTT.js adapter's
QoS/persistence and a real Mosquitto restart are outside this deterministic local validation.

Checkpoint files are cleartext measurement data protected by their destination's access control,
not encrypted credentials. POSIX mode 0600 is requested; Windows uses inherited ACLs. Snapshot
persistence is explicit and does not assert fsync/crash durability or distributed exactly-once
semantics. See [the recovery guide](../checkpoint-recovery.md) for all operational bounds.
